How it works

1 · CONTRACT

You set the scope

/receipt-init reads your project and proposes your real test, lint and build commands. You set the goal; the agent can never edit the contract.

2 · ENFORCE

Every tool call is checked

Writes outside scope, secrets, and risky shell commands are blocked or sent for approval, with the reason. Claude is told its scope up front, so it rarely tries.

3 · RECEIPT

A verdict from evidence

/receipt runs your checks, compares git, and signs a shareable receipt bound to the exact git tree, with a step-by-step timeline and authorship counts.

4 · GATE

Pull requests prove it

The GitHub Action passes a pull request only when a trusted receipt covers exactly its head commit. One edit after the receipt, and it fails.
